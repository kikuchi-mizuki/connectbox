## 3. 会社の姿勢（バリュー）とHPへの入れ方

### 3.1 バリュー本文（社内の原典）

> **『目先ではなく、未来を選べ』**
>
> 私たちは日々のあらゆる判断において、自分本位ではなく、相手・仲間や家族・会社の未来にとって最善かを考える。
> 目先の利益よりも長期的な信頼を優先する。
> その積み重ねが、人から選ばれ続ける組織を創る。

設定理由（社内）: 人は意識的な決定を1日に多く繰り返す。その判断が自分軸ではなく、相手や大切にしている人のための行動になっているかを見るためのフィルタ。

これは顧客向けキャッチコピーではない。**会社としての姿勢・判断基準**である。

### 3.2 HPでの扱い（確定）

- トップ（Hero）の主コピーにはしない
- 宣言文として全面に出すのでもなく、**サイト全体の判断から汲み取れる**ようにする
- 「1日1万回」「自分軸ではない」は社内の話。HP本文には出さない
- 文言として出すなら、会社ページ（またはトップの「考え方」）に短く

訪問者に残したい印象は、標語ではなく次の判断である。

> 目先の契約を急がず、相手の将来に残る持ち方を勧める会社だ。

### 3.3 姿勢の翻訳（コピー・構成の原則）

カタログであっても、領域を「今の穴埋めメニュー」として並べない。

| やらない（目先） | やる（未来が伝わる） |
|------------------|----------------------|
| 「今すぐ売上」「限定」「即契約」 | 相談・棚卸しから。契約はそのあと |
| 「全部丸投げで楽になる」だけ | 楽になるだけでなく、あとから回る／選ばれ続ける |
| 安い・早いだけを前面 | 続ける前提、長期の信頼 |
| 6領域を機能名だけ並べる | 各領域を「持ち方を変える」として1〜2文で書く |
| 「私たちがすごい」が主語 | 主語は相手の会社（事業）の未来 |
| 今月の受注都合で急かすCTA | 今やらなくていいことも言える余白 |
| 他領域へ無理にクロスセル | カタログとして選べる。押し売りしない |

### 3.4 カタログと姿勢の両立

売り方は領域ごとの別サービス（確定）。  
考え方は横断で一つ（確定方針）。

トップは「箱の中身の目次」、各詳細は「その領域のサービスページ」。  
横断で共通なのは、始め方（いきなり契約しない）と、目先の穴埋めにしない言い方。

## 4. 目的・ゴール

### 4.1 目的（確定）

社員10〜50人規模の社長、個人事業主、新規事業や採用・コストに追われている事業者に、コネクトボックスの6サービスを見せ、関心領域の相談（LINE）につなげる。

### 4.2 コンバージョン（確定）

| 項目 | 内容 |
|------|------|
| 主CTA | LINE公式アカウント（既存: https://lin.ee/RiVp6pb） |
| 配置 | Header／Hero／各領域ページ／最終CTA／（スマホ）下部固定 |
| 非ゴール | いきなり契約・詳細見積の完結 |
| CTA文言 | 「LINEで相談する」系。今すぐ依頼、ではない |

フォーム・予約カレンダー・電話は初版に置かない（確定: 今回やらないことに準ずる）。

領域ページのLINEは、可能なら流入が分かるようにする（仮置き。例: 同一URLでも、ページ名をLINE初回メッセージの案内に書く。計測パラメータは未決）。

### 4.3 流入（確定）とページの役割

| 流入 | HP側ですること |
|------|------------------|
| 営業メール | メールで触れた領域と、詳細ページの見出しを揃える |
| テレアポ | 話した領域のURLを案内できる（領域ごとにURLが分かれていること） |
| SNS | OGP（タイトル・説明・画像）をページごとに出す |
| 検索 | 領域ページをインデックス対象にする。ブログは作らない |
| 紹介 | トップが「何の会社か」を短時間で説明できること |

検索はMustに近い（流入に含まれるため）。記事量産はしない。各ページの title / description / h1 を領域語で整える（仮置き）。

## 5. ターゲット

### 5.1 一番ほしい客（確定）

- 社員10〜50人の社長
- 新規事業が忙しい会社
- 採用が止まっている会社
- コストを抑えたい事業者
- 個人事業主

決裁者は本人（社長・事業主）が多い想定。大企業の調達・比較検討は主対象にしない。

### 5.2 想定課題（仮置き）

- コア以外に時間が取られ、未来の手を打てない
- 人を足す判断が目先の穴埋めで、持ち方が変わらない
- マーケ・事務・採用・戦略が誰かの兼務になっている
- 外注はしているが、安さ・速さだけで残る型がない
- 採用を止めている／止まっているのに、業務は減らない
- 個人事業・少数体制で、機能を社内に持てない

コピーは「中小企業の経営企画向け」に寄せすぎない。個人事業主が読んでも自分のことだと思える語を残す。

## 6. サービス定義

### 6.1 コネクトボックスとは（確定）

6つの**別サービス**を束ねるカタログ名。  
セット売りや月額の固定箱としては出さない。関心のある領域から入れる。

**ひとつを打ち出さない。** 看板領域はない。6領域は同列の別サービスとして並べる。

### 6.1.1 「同列」の定義（確定）

同列とは、次の3層をすべて満たすこと。

| 層 | 意味 | 要件 |
|----|------|------|
| 視覚 | 6領域に優劣がない | カード・ナビ・フッターでサイズ・バッジ・強調色を揃える |
| 導線 | どれから入っても同じ深さ | 各領域に同等の詳細ページ。セット契約を前提にしない |
| 物語 | トップが特定1領域の翻訳にならない | Hero・お悩み・考え方が、1領域だけを主語にしない |

**例外（許容）**: バックオフィスだけ既存LPへつなぐ。HP内では厚く見せない。特化ページは「別チャネル」と明記する。

### 6.1.2 トップの主コピー（確定: 1-B）

トップHeroは**選び方**を言う。領域の中身や箱の価値を一言にしない。

| 項目 | 文言（確定） |
|------|----------------|
| 主コピー | **必要な領域から、別のサービスとして始める。** |
| サブ | 6領域名を列挙し、まとめて契約不要であること |

使わない（トップHero）: 「足りない機能を、採用せずつなぐ」— BPO寄りになり、戦略・コーチングが後ろに下がる。

### 6.2 6領域（確定。同等・別サービス）

並び順は固定（4-A）。**先頭を看板にしない**— 並びは仮の整理順であり、WEBマーケを主役にしない。

| 並び | 領域 | スラッグ（仮） | 目先（主にしない） | 未来（HPで書く） | 特記 |
|------|------|----------------|--------------------|------------------|------|
| 1 | WEBマーケ | `/services/web-marketing` | 今月の広告だけ回す | 選ばれ続ける導線と信頼 | |
| 2 | バックオフィス | `/services/back-office` | 処理の穴埋め | 属人化しない回し方 | 詳細から既存LPへつなぐ |
| 3 | 採用・人事 | `/services/hr` | 欠員の急場しのぎ | 長く働ける採用と定着 | |
| 4 | 組織コーチング | `/services/coaching` | その場の火消し | 判断の軸を揃える | |
| 5 | 経営戦略 | `/services/strategy` | 今月の数字合わせ | 未来を選ぶ意思決定 | |
| 6 | 既存事業ブラッシュアップ | `/services/business-upgrade` | 延命・小手先の改善 | 次に選ばれる理由を磨く | |

各詳細ページは「その領域のLP」に近い情報量でよいが、トーンはHP（煽らない）。他領域への導線はフッターまたは「ほかのサービス」に同等リンクで置く。

### 6.3 事例の代替（仮置き）

実名事例は出さない（今回やらないこと）。  
各領域ページに「よくある始め方」を2〜3点置く。トップに横断の始め方は置いてもよいが、6領域をセット契約する前提の書き方はしない。

## 8. ページ構成

各ページ1目的。バリューはHeroに置かない。

### 8.1 トップ `/`（確定）

| # | セクション | 役割 |
|---|------------|------|
| 1 | Header | コネクトボックス（ロゴはT-connect）。相談CTA |

| 3 | サービス一覧 | 6領域を同等カード。**詳しく見る → 各領域LP**（`/services/...`） |
| 4 | 考え方 | 横断の共通姿勢。**2-C: 残すがトップでは一段小さく** |
| 5 | 進め方 | 相談の流れは**トップのみ**（LPでは繰り返さない） |
| 6 | FAQ | 横断FAQは**トップのみ** |
| 7 | 最終CTA | LINE |
| 8 | Footer | 社名はT-connect。表のサービス名はコネクトボックス。6領域は各LPへ |
| 8 | 最終CTA | LINE |
| 9 | Footer | 社名はT-connect。表のサービス名はコネクトボックス |

### 8.2 領域LP（6ページ・確定方針）

トップの「詳しく見る」は、各領域のLP（`/services/{slug}`）へ遷移する。ページ内ではその領域の中身だけを書く。共通の流れ・FAQ・他領域カタログは置かない（フッターで足りる）。

| # | セクション | 役割 |
|---|------------|------|
| 1 | Header | トップに同じ |
| 2 | Hero | その領域の顧客変化＋LINE |
| 3 | お悩み | その領域のみ |
| 4 | できること | 具体の支援範囲 |
| 5 | 考え方 | その領域での「持ち方を変える」 |
| 6 | 始め方 | よくある始め方 2〜3 |
| 7 | 最終CTA | LINE |
| 8 | Footer | 共通 |

既存のバックオフィス特化LP（`01_lp`）はメール誘導用として残す。HPの「詳しく見る」はHP内の領域LPへ揃える（6領域同列）。

### 8.3 会社 `/company`（確定）

会社概要はダミー可。公開前に差し替える。掲載項目:

商号、英文名、サービス名、代表者、設立、資本金、従業員数、所在地、アクセス、電話、FAX、メール、Webサイト、営業時間、適格請求書発行事業者登録番号、取引銀行、事業内容、姿勢（バリュー）、LINE CTA。

サービス一覧はトップと重複するため、会社ページには置かない。

### 8.4 Heroコピー（確定: 1-B）

- 主コピー = **必要な領域から、別のサービスとして始める。**
- サブ = 6領域名の列挙 ＋ まとめて契約不要
- バリューの標語は主コピーにしない
- 特定領域の価値（採用せずつなぐ、等）は主コピーにしない

### 8.4.1 お悩み（確定: 3-B）

トップのお悩みは、社長の状態の羅列ではなく、**6領域それぞれに1本**。

| 領域 | お悩み（1行） |
|------|----------------|
| WEBマーケ | 広告費をかけても、問い合わせが残らない |
| バックオフィス | 経理や総務に時間が取られ、本業に手が回らない |
| 採用・人事 | 採用が止まっているのに、業務は減らない |
| 組織コーチング | 社長がいないと決まらず、同じ議論が繰り返される |
| 経営戦略 | やることは増えるが、捨てる判断ができない |
| 既存事業ブラッシュアップ | 既存事業は回っているが、次の一手が小手先になっている |

表示は領域名を明示し、サービス一覧と同程度の同等レイアウトとする。

### 8.5 考え方セクション（確定: 2-C）

横断の共通姿勢として残す。ただしトップでは**一段小さく**— 大見出しの主役セクション（全面ダーク等）にしない。

出してよい短文:

> 目先ではなく、未来を選べ。  
> 人を足す、安く済ませる、今月だけ乗り切る、ではなく、あとから選ばれ続ける持ち方に変える。

「人を増やす前に、持ち方を変える」は共通の考え方として触れてよいが、トップの主見出し級にはしない。各領域詳細では、その領域版の考え方を主に書く。

社内向けの「1万回」「家族」は書かない。

### 8.6 進め方（仮置き。4ステップ）

1. LINEで相談  
2. オンラインでヒアリング  
3. 適用範囲の提案（やらなくてよい範囲も含む）  
4. 引き継ぎ後、その領域の支援開始
